\chapter{前言}

真传一句话，假传万卷书。具体到计算机里的某一项技能，一句话当然说不完。但一个人想学计算机体系结构，也别上来就给他推荐《计算机体系结构：量化研究方法》（\emph{Computer Architecture: A Quantitative Approach}），这谁能看懂。

不如先讲讲，自己是怎么一步步走到 CPU 这里来的。

小时候很想知道计算机是怎么工作的，却从来不敢去想硬件是怎么造出来的。在那时的我眼里，硬件像是凭空长出来的魔法，就像这个世界本来的设定一样摆在那里，不容质疑，甚至不会让人好奇它是怎么工作的。唯一知道的是，CPU 一年比一年快，家里的电脑很快就落伍了。

到了高中和大学，开始学黑客技术。它是一条通往底层软件的通道，是我的“白兔”——就像《爱丽丝梦游仙境》里那只白兔，跟着它，就掉进了另一个世界。这一次，终于敢去好奇了：那些黑客工具是怎么做出来的？

编程是从 Pascal、BASIC 学起的，后来是 C。接着知道了“API”这个词，它是操作系统提供的服务；顺便也才弄明白，原来还有一个东西叫操作系统。比起在 C 里用 \texttt{printf} 打印三角形，能调用 Win32 API 的那一刻，仿佛一下子有了力量，好像在计算机的世界里，没有什么做不到的。

然后是汇编，是操作系统内核的代码。泄露出来的 Windows 内核代码、开源的 Linux 内核代码，都一页页地读过。也试着写驱动，还想过写一个小小的操作系统。这件事其实没有真的做成，但赵炯的《Linux 内核完全注释》是认真学过的，这本书逐行注释了 Linux 0.11 内核的源代码。大学时，还在一台真实的 PC 上装起了 Linux 0.11 内核。

后来又自己写了一个 TCP 协议栈。起因是当时写的 rootkit 能绕过所有商业软件防火墙，传数据却很慢：发一个包、确认一次，再发下一个。为了解决这个问题，从 4.4BSD 的代码里学会了滑动窗口。

做过不少 rootkit 项目之后，目光转向了更底层的东西，比如 CPU 是怎么工作的。x86 汇编只给了一点线索，离真正弄懂 CPU 还差得很远：它是怎么工作的，长什么样子，连想象都想象不出来。

就在那时，有机会参加了一个项目：用软件模拟一颗 x86 CPU，在里面运行恶意代码。分给我的是内存模拟的部分。不过这部分做的大多还是操作系统层面的事，比如分页、保护页（guard page）、写时复制（copy-on-write）——内存其实不需要真的去模拟，模拟器本身就运行在内存里。但这正是需要的那条线索。古人说“阅藏知津”，读经要先知道渡口在哪里。这个项目，就是通往大海的那个渡口。

又过了几年，自己动手写了一个 x86 CPU 模拟器。它并不完整，却让我弄明白了怎样解析二进制代码，一条指令又是怎样由操作码、ModR/M 字节这些部分组成的。真正的 CPU 之旅，就是从这里开始的。

说这些，并不是想表示已经走到了终点，好像已经知道怎么造出一颗现代 CPU。离那里还很远。但确实在往那里走，而且这条路在眼前越来越清楚。

这本书，就是沿着这条路留下的记录。我还在追逐着我的小白兔。
